# 3D 字母点选验证码设计

在 `svg-captcha` 包内新增独立入口 `captcha.letter3d`。服务端生成一张自由排布的场景图，字母散落在连续的画布坐标上。用户阅读图外的一句提示，直接点击图中的字母。接入方可以指定单选、多选，或者让生成器逐题抽取。每题判断颜色、朝向、字母中的一至三个属性。

## 作答方式

| 模式 | 出题保证 | 图上交互 | 提交条件 |
| --- | --- | --- | --- |
| 单选 `single` | 全图恰有 1 个正确对象 | 可以在图内任意位置落一个点，再点一次就把点移到新位置 | 最终坐标落在正确字母上 |
| 多选 `multiple` | 首版每题有 2 至 3 个正确对象 | 每点一次，原地留下一枚小点。可撤销最近一次落点，顺序任意 | 每个正确字母各命中一次，所有点均须命中目标 |
| 混合 `mixed` | 签发时决定当题为单选或多选，按对应规则生成 | 界面明确标出当题模式 | 一次提交只适用于签发的那一题 |

“单选 / 多选”控制正确对象的数量，“一至三个条件”控制每个对象需要满足的属性，两者独立。单选也可以考三个条件，多选也可以只考一个条件。生产环境由签发端决定模式。样题中的模式开关用于体验，切换会生成一张新图并清空已选项。

## 题目与文案

朝向分为正对着你、朝屏幕左侧、朝屏幕右侧。每个目标同时满足题干给出的全部条件。直接题支持三个属性的七种非空组合。参照题将朝向指定为“与参照物同向”，再任选颜色、字母，共四种组合。两类题均可单选或多选。

| 题目 | 文案示例 |
| --- | --- |
| 直接 · 单选 · 一个条件 | 请点选正对着你的字母。 |
| 直接 · 单选 · 两个条件 | 请点选朝屏幕左侧的橙色字母。 |
| 直接 · 多选 · 三个条件 | 请选出所有朝屏幕右侧的蓝色 T。 |
| 参照 · 多选 · 一个条件 | 除了蓝色 T，请选出所有和它朝向相同的字母。 |
| 参照 · 单选 · 两个条件 | 请点选和蓝色 T 朝向相同的橙色字母。 |
| 参照 · 单选 · 三个条件 | 请点选和蓝色 T 朝向相同的橙色 F。 |

“蓝色 T”负责指定全图唯一的参照物。参照物的描述不计入目标条件数，参照物本身始终排除在答案外。如果参照物也符合目标描述，文案以“除了蓝色 T”开头。直接题使用“正对着你”表达字面朝向用户。

## 从规则生成一张图

1. 确定作答模式、直接或参照题型、属性组合和目标数量。先生成结构化规则，再生成题干。参照题检查参照物可被唯一描述，并排除规则矛盾，例如要求另一个目标也是唯一的蓝色 T。
2. 按目标数量构造匹配对象，属性相同的字母也视为独立实例。给每个条件构造一个只差这一项的干扰对象。例如找“和蓝色 T 同向的橙色 F”时，放入同向的紫色 F、异向的橙色 F、同向的橙色 E。剩余对象从不匹配的组合中抽取。
3. 从整幅画布的连续二维范围采样中心位置。随机打散对象的放置顺序，按投影后包含正面和侧壁的完整字形尺寸留出间距，拒绝过近或越界的位置。位置、尺寸和绘制顺序的抽样均独立于正确性。
4. 经过有限次尝试仍无法布置时，整图重新采样。可优先减少可选的填充对象，保留参照物、所有目标和每个必要的干扰对象。在支持的候选数和尺寸内仍失败时明确返回生成错误。任何重试都必须保留调用方指定的模式和条件数。
5. 对最终场景重新应用规则，核对参照唯一、答案基数正确且与预设的目标集合一致。删去任一目标条件，排除参照物后的匹配集合都应变大。为每个字母分配本题内部编号，输出一张合成图，服务端保留点位核验数据。

## 渲染与命中

- **字模与朝向**　`lib/letter3d/` 管理自己的粗笔画字模、几何投影、光照、光栅化和 PNG 输出。所有字母完整可见。可从 `E F H K L R T` 开始，正面约 0°，侧向左右各约 38°。每个字母先在同样的局部相机下投影，再平移到抽取的位置。这样同向字母分处画面两端也有一致的方向线索。
- **自由散布**　画布为 480 × 360 逻辑像素，每图 7 至 9 个字母。将投影前字模高度的 54–90 像素范围按当题字母数量等分，每段抽一个随机字号，再随机分配给目标、参照和干扰字母。按缩放、投影后的字形轮廓留出间距，判题使用同一份几何数据。背景和图边保留留白。
- **落点反馈**　整张 PNG 接收点击或轻触。标记的中心就是输入坐标，点在空白处也显示同样的小点。每次增加、替换或撤销只更新点标记。点击是否正确只在提交时反馈。
- **坐标合同**　取指针相对实际显示图像左上角的位置，分别除以显示图像的宽和高，得到归一化坐标 `{x, y}`。合法范围为 `0 ≤ x < 1`、`0 ≤ y < 1`。服务端映射为 `floor(x × 原图宽)`、`floor(y × 原图高)`。等比缩放会保留相对坐标。若使用 `object-fit: contain`，图像内容以外的留白不接收落点。
- **命中依据**　渲染器在服务端为原图像素记录可见面的字母编号，0 表示背景。字母正面、可见侧壁和描边均算命中，笔画之间露出的背景仍是空白。抗锯齿边缘统一按像素中心的几何归属判定。提交时逐点查出对象编号，背景、错误字母或同一字母被点两次均判错。有效编号的集合须与目标集合完全相等。

## 包接口与服务端接入

包根导出 `captcha.letter3d`，也可单独引用 `svg-captcha/letter3d`。该入口有独立的默认设置，并导出下列类型和函数。[TypeScript 声明](../letter3d.d.ts)

```ts
type SelectionMode = 'single' | 'multiple'

interface Options {
  selection?: SelectionMode | 'mixed'
  mode?: 'direct' | 'relative' | 'mixed'
  constraintCount?: 1 | 2 | 3
  useColor?: boolean
}

interface Point {
  x: number
  y: number
}

interface Challenge {
  selection: SelectionMode
  prompt: string
  data: Buffer
  width: number
  height: number
}

interface Solution {
  selection: SelectionMode
  width: number
  height: number
  objectAtPixel: Uint8Array
  targetIds: number[]
}

declare function create(options?: Options): { challenge: Challenge, solution: Solution }
declare function verify(solution: Solution, points: unknown): boolean
```

例如 `create({selection: 'single', mode: 'relative', constraintCount: 2})` 总是生成一道有唯一目标的双条件参照题。省略 `selection` 或 `mode` 时各自采用 `mixed`。默认启用颜色。关闭 `useColor` 后只考字母和朝向，参照物用全图唯一的字母指定。显式要求三条件且关闭颜色时抛出 `RangeError`。

- **签发与刷新**　服务端保存随机挑战 ID、`solution`、会话、操作和过期时间。公开响应只含挑战 ID、当题模式、提示、图片尺寸和题图。刷新使上一题失效并清除旧点。
- **提交与核验**　客户端提交 `{id, points: [{x, y}, ...]}`。服务端原子取出并消耗绑定当前会话和操作的有效题目，检查点数、坐标类型、有限性及范围，再按 `objectAtPixel[py * width + px]` 逐点判定。单选只接受一个点，多选要求点数恰好等于本题目标数。一次有效绑定的提交消耗本题，签发和核验分别限流，题图及签发响应使用 `Cache-Control: private, no-store`。
- **可访问性**　提供整图键盘定位，方向键移动光标，空格或回车在光标位置落点，撤销按钮使用原生键盘交互。另提供无颜色模式及非视觉验证入口。图片替代文字描述人机验证的用途。[W3C 对非文本内容的说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-content.html)

## 验收

1. 对七种直接组合、四种参照组合分别测试单选和多选，覆盖无颜色模式、矛盾配置、单选唯一性、多选 2 至 3 个目标、参照唯一性和条件有效性。
2. 批量核对正面、侧壁、描边、字腔留白和相邻空白的像素归属，覆盖图像四边及越界坐标。抽查不同随机种子下的位置分布，记录布局重试率和生成用时。
3. 在手机和桌面验证标记中心与点击位置一致、空白可落点、单点替换、多点撤销、重复点中同一字母、换题清空及键盘定位。等比缩放、页面滚动后，原图同一位置应映射到同一像素。在接入服务检查重复提交、过期和并发消费。
4. 先用同一字模测试左、正、右三种姿态，再测试完整题目。按单选、多选、直接题、参照题分别统计首次通过率、用时和换题率，机器评测单独记录。可用各方向辨识率 ≥95%、人类整题首次通过率 ≥90%、中位用时 ≤8 秒作为待验证的首轮目标。
